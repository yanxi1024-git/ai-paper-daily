# ReliabilityBench：你的 AI Agent 真的准备好上生产了吗？

> 📌 **一句话亮点**：现有 Agent 评测只看"能不能跑通一次"，ReliabilityBench 首次用混沌工程的思路测 Agent 在真实生产环境下的可靠性——结果发现越复杂的 Agent 反而越脆弱。

---

## 🎯 解决了什么问题？

现在评测 AI Agent 的方式有个根本问题：**只看单次成功率**。

ToolBench、AgentBench、SWE-bench 这些主流基准测试，都只报告 Agent 跑一次能不能完成任务。但真实生产环境根本不是这样：

- 用户不会用标准模板提问，会换着法子说同一件事
- API 会超时、限流、返回残缺数据
- 同一个任务多跑几次，结果可能不一样（LLM 的随机性）

ReliabilityBench 的出发点是：**与其问"这个 Agent 能不能订机票"，不如问"跑1000次，在各种输入变化和故障下，成功率还剩多少？"**

---

## 🔬 方法概要

论文提出了一个 **三维可靠性评估框架** R(k, ε, λ)：

### 维度一：一致性 Consistency (k)

同一个任务跑 k 次，全部成功的概率。pass@1 是 96.9%，但 pass@5 可能只有 85%。**单次成功不代表可靠。**

### 维度二：鲁棒性 Robustness (ε)

对任务描述施加扰动，看 Agent 还能不能成功：
- ε=0：原始描述
- ε=0.1：同义词替换
- ε=0.2：语句重排 + 增加干扰信息
- ε=0.3：改写 + 中途修正

> 核心创新：**Action Metamorphic Relations**——判断正确与否不看输出文本是否相似，看**最终状态**是否一致。订到了同一个会议室就算对，中间怎么绕的不重要。

### 维度三：容错性 Fault Tolerance (λ)

借鉴 Netflix Chaos Monkey 的思路，在工具调用中注入故障：
- 超时 (timeout)
- 限流 (rate limit)
- 部分响应 (partial response)
- Schema 漂移 (schema drift)

λ 控制故障概率：0.1（5-10%）、0.2（15-20%）、0.3（25-30%）。

### 可靠性曲面

三者组合在一个三维曲面 R(k, ε, λ) 上，可以直观看出 Agent 在什么条件下开始崩溃。

## 📊 关键结果

实验设计：
- **模型**：Gemini 2.0 Flash、GPT-4o
- **架构**：ReAct（简单）、Reflexion（复杂，带自我反思）
- **领域**：日程安排、旅行预订、客服支持、电商
- **规模**：1280 个测试 episode，25+ 个领域工具

### 核心发现

| 发现 | 数据 |
|------|------|
| **扰动导致显著退化** | pass@1 从 ε=0 的 96.9% 跌到 ε=0.2 的 88.1%（-8.8%） |
| **pass@1 高估可靠性 20-40%** | 单次成功的 Agent，多跑几次可靠性断崖下跌 |
| **限流是最致命的故障** | 消融实验中比混合基线低 2.5% |
| **简单 > 复杂** | ReAct 在压力下优于 Reflexion |
| **性价比悬殊** | GPT-4o 成本是 Gemini 2.0 Flash 的 **82 倍**，可靠性仅差 -0.6% |

## 💡 为什么值得关注

### 1. 对 Agent 开发者的直接启示

> **别迷信复杂架构。** Reflexion 加了自我反思机制，理论上应该更强——但在真实压力下反而更脆弱。复杂度引入的额外推理步骤，在故障场景中变成了额外的失败点。

### 2. 对选模型的启示

> **别盲目追最强模型。** GPT-4o 成本是 Gemini Flash 的 82 倍，可靠性几乎一样。如果做高并发的 Agent 服务，这个成本差异可以直接决定商业模式是否成立。

### 3. 对 Agent 评测行业的影响

这是第一个把 **SRE（Site Reliability Engineering）** 和 **混沌工程** 方法论引入 Agent 评测的工作。之前大家评测 Agent 像评测一个函数，ReliabilityBench 让评测像评测一个在线服务——这才是 Agent 该有的待遇。

### 4. 与 AI Agent 创业的关系

如果你在用 Agent 做客服、做自动化交易、做供应链——你的 Agent 在 demo 里跑通一次远远不够。你需要知道：
- 用户换种问法会不会崩？
- 外部 API 挂了能不能优雅降级？
- 跑 100 次成功率是多少？

**ReliabilityBench 提供了一个可复现的测试框架，而不是又一个"看起来很强"的 benchmark。**
