# 你的 AI 真的靠谱吗？有人用混沌工程给它做了次压力测试

> 📌 我们经常说某个模型"很强"、某个 demo "跑通了"，但很少认真问一句：把它扔到真实世界的乱糟糟的环境里，到底有多可靠？由 Aayush Gupta 等人的 "ReliabilityBench: Evaluating LLM Agent Reliability Under Production-Like Stress Conditions" 这篇论文给了一个让人有点不安的答案。

## 🎯 我们在问什么问题
现在主流评测基本就是跑一遍 benchmark 看分数。但真实世界不是 clean room。

用户不会按你预设的模板提问——他们会换说法、加废话、中途改主意。外部 API 会超时、会限流、会返回半残的数据。同一个问题问两遍，LLM 可能给出不同的答案——有时候对，有时候莫名其妙。

论文发现，**单次成功率（pass@1）比真实可靠性高出了 20-40%。** 也就是说，benchmark 里看着很漂亮的数字，放到生产环境里可能要打不小的折扣。

## 🔬 方法概要
作者搞了一个三维评估框架 R(k, ε, λ)，想法挺干净的：

- **k（一致性）：** 同样的事做 k 次，全对的概率。pass@1 可能是 96.9%，pass@5 就不好说了
- **ε（鲁棒性）：** 换个说法、调个顺序、加点废话，还对不对。有意思的是，他们不判断"输出文本是否像"，只看"最终状态是否一致"——订到同一个会议室就算对，中间怎么绕的不管
- **λ（容错性）：** 模拟真实故障——超时、限流、残缺响应、接口格式偷偷变了——看系统能不能抗住。这个思路直接来自 Netflix 的 Chaos Monkey

这三个维度叠在一起形成一个"可靠性曲面"，哪个维度先崩、崩在什么条件下，一清二楚。

## 📊 关键数据
他们测了 Gemini 2.0 Flash 和 GPT-4o，两种架构（简单的 ReAct 和带自我反思的 Reflexion），四个领域（日程、旅行、客服、电商），总共 1280 个测试 episode。

| 发现 | 数据 |
|------|------|
| 轻微扰动就能造成明显退化 | ε=0→96.9%, ε=0.2→88.1%（掉了 8.8 个百分点） |
| pass@1 严重高估可靠性 | 高了 20-40% |
| 限流是最要命的故障 | 比其他故障类型多拖垮 2.5% |
| 复杂架构压力下反而更脆 | 带反思的 Reflexion 打不过简单的 ReAct |
| 最贵的不一定最可靠 | GPT-4o 成本是 Gemini Flash 的 82 倍，可靠性只差 -0.6% |

最后一个数据我看完真的愣了一下——82 倍的价差，靠谱程度几乎一样。

## 💡 读后感和碎碎念
**复杂不等于可靠。** Reflexion 加了自我反思，听起来应该更稳。但在故障场景下，多出来的推理步骤本身就成了新的脆弱点。这个反直觉的结果让我怀疑：我们是不是在一些地方把系统搞得太"花哨"了？

**按 benchmark 排名选模型可能是个很贵的习惯。** 82 倍的成本差异摆在那，但 benchmark 分数看不出这个。不是说便宜的就一定好，但至少提醒我们：只看性能分选模型，有点像只看百公里加速买车。

**评测思维的一次有意思的跨界。** 之前大家评测 AI 像评测一个函数——输入→输出→对不对。这篇论文把它变成了像评测一个在线服务——能不能扛压、能不能容错、能不能保持一致性。这个视角切换本身就很值得关注。
