Agent 的记忆不该只在开局用一次——ICML 2026 说该让它边跑边想

你的 Agent 有一个"记忆库"，但它只在任务开始时翻一下，之后就全靠硬撑。AdaMEM 给了 Agent 一种"边跑边从经验里抽策略"的能力，ALFWorld 相对提升 17%，而且不需要改模型参数。

————————————————————

AdaMEM 在零样本 prompting 下就能工作，但作者发现 untrained 模型生成的策略往往太过笼统——"仔细检查每一步"这种废话对决策帮助不大。

于是他们提出了 Step-MFT（Step-wise Memory Fine-Tuning），一个很巧妙的训练技巧：

传统做法：跑成功一条轨迹，认为轨迹上每一步的策略都是好的 → 全都用来微调。但问题在于，有些策略根本没改变 Agent 的行为——它只是说了些"正确的废话"。

Step-MFT 的 insight：一条策略有没有用，看它是否改变了 Agent 的动作选择。 基于这个简单的直觉：

1. 用 AdaMEM-high 跑训练集，收集每步的 (状态, 策略, 动作) 元组
2. 过滤：如果加上策略前后 Agent 选了同一个动作 → 策略没提供增量价值 → 丢弃
3. 只保留"策略确实改变了决策"的样本做监督微调

这个方法不需要价值模型、不需要蒙特卡洛 rollout、不需要专门训练 critic——纯靠"动作是否改变"这个信号做 rejection sampling。高效，而且直觉上就很合理。

效果：加上 Step-MFT 后，ALFWorld 相对基线提升从 13% 跳到 17%，WebShop 从 11% 跳到 13%。

AdaMEM 的核心想法很干净：长期记忆存原始经验，短期策略在线动态生成。

架构分两层：

长期轨迹记忆（Long-Term Trajectory Memory）
- 离线阶段收集成功的完整轨迹
- 每一步存一个 key-value 对：key 是当前状态的 embedding，value 包含"当前状态 + 当时采取的动作 + 后续走向成功的剩余轨迹"
- 这是一个密集索引的经验库，不参与在线推理的 token 消耗

短期策略记忆（Short-Term Strategy Memory）
- 在线、按需、针对当前状态生成的自然语言策略
- 不是把原始日志扔给 Agent，而是让 Agent 基于当前状态去检索相似经验，然后当场合成一条针对性策略
- 策略用完后可以丢弃（high 模式）或保留到需要刷新为止（low 模式）

这个设计的精妙之处在于：存储用的是离线经验（不烧 token），但策略生成是在线、针对当前状态的。 存储和抽象解耦了。

• 模式：策略生命周期
• 成本：|------
• **AdaMEM-high**：每步生成新策略，用完即弃
• token 消耗高：| **AdaMEM-low**
• token 效率高：可能在策略过期时延迟响应

读这篇的时候我忍不住对照了一下我们自己的 Agent Memory 实践：

1. 记忆分层的思路高度一致。 我们也在探索"原始日志"vs"提炼策略"的分层，AdaMEM 从 ICML 的视角给了理论支撑和一个清晰的架构模板。

2. "在线生成策略"这个想法很值得一试。 我们目前的 memory 更像 AdaMEM 批评的"静态检索"——在 session 开始时加载，中间不更新。如果能让 Agent 在长对话/长任务中自行判断"我需要从历史经验中重新合成一条策略"，可能会显著提升稳定性。

3. Step-MFT 的"动作改变=策略有效"这个过滤标准，可以直接用到我们的自我改进流程里。 我们在做 self-improving-agent 的时候，也需要筛选"哪些经验值得记住"——这篇给了一个简单但有理论依据的判据。

4. 存储解耦的工程意义。 AdaMEM 的长期记忆里存的是 raw trajectory，策略生成在推理时做。这意味着记忆库可以用便宜的 embedding 检索，策略合成用模型能力——两层的 scaling 是独立的。这对我们设计可扩展的记忆系统很有启发。
